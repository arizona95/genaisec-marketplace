## 📐 문서 구조 — 섹션 순서·제목·번호, 표/그림이 어디 위치하는지, 별첨 구성(뼈대)
# 문서 뼈대 (배치·순서 전담) — 위반 교정 우선

## 0. 입력은 셋뿐 (불변)
① 이 skill 폴더 안 로컬 파일 ② `src/`(실자료 · `src/_srcimg/` 실제 캡처 · `src/_summary/` 정리노트) ③ `example/`(서식 기준 예제). 그 밖의 파일·다른 산출물·개체 번호(후보 번호 등)는 열지도 언급하지도 않는다. 피드백에 번호가 나와도 번호는 쓰지 말고 '무엇이 왜 좋았는지'만 일반 원리로 적용한다.

**날조 금지(전 문서 공통, 여기 한 번만):** 버전·모델명·요금·URL·인용문·수치는 `src`(우선 `_summary`) 원문 값 그대로. 없으면 `- (src 미기재)`로 비운다. 증적은 `_srcimg` 실제 캡처만.

## 1. 시각 세부는 서술로 판단하지 말고 example 을 재서 복제한다 (1차 규칙)
정렬·여백·열폭·표 폭·들여쓰기·글자 크기 단계·테두리·음영·자간·캡션·줄간·이미지 크기는 매 요소(제목/날짜/절 본문/표 n/구성도/결론 박스/종결표기/별첨 k)마다 **example 의 같은 위치를 열어 눈으로 재서 그대로 옮긴다.** example 에 없는 요소는 추가하지 않는다(표 캡션 `<표 n>`, `【 … 】` 장식 박스, 자체 소제목·요약 절 신설 금지). 재기 어려운 것만 아래 명시값을 쓰고, 충돌 시 **example 우선**.

## 2. 🚨 실제로 틀렸던 항목 — 교정표 (여기만 외워도 대부분 산다)

| # | 틀렸던 것 | 맞는 것 |
|---|---|---|
| 1 | 제목에 '보안**성** 검토 결과' | `<대상명> 보안검토 결과` — '성' 넣지 않음. 5절 제목과 문구 일치 |
| 2 | 날짜 표기 흔들림 | 제목 바로 아래 오른쪽정렬로 작성일만, `YYYY. M.DD` (월은 소재 그대로 1자리 가능, 일은 2자리). 예: `2026. 8.08` |
| 3 | 4절에 '모집단 34개 / 20개' 수치 계층 추가 | **적용 모수 33만 쓴다** — `생성형 AI 23 + AI Agent 10 = 33`. example 에 없는 모집단 수치·자체 분류·'서비스별 특화항목' 신설 금지. 영역 구분·항목 번호·항목명은 example 코드 체계 그대로 승계 |
| 4 | 5절 요약에 제3판정 추가(`?(1)`) | 어형 고정: `- 충족(n), 각사 검토 필요(n)` — 항목을 늘리지 않는다. 미확인은 별첨1 셀에서 사유와 함께 처리 |
| 5 | 개요표에서 '대상 버전' 행 누락 | 3절 제목 괄호와 중복돼도 **독립 행으로 반드시 존재** |
| 6 | 결과표에 '구 분' 열을 덧붙여 3·4열화 | 5절 결과표는 **2열 50/50** (상세내용 / 대응 방안) 고정 |
| 7 | 별첨1·2 '결과' 열이 좁아 `각사 검 / 토`, `(Enterpr / ise 전 용)` 처럼 어절이 글자 단위로 깨짐 | 결과 열 어휘를 짧은 어절 4종으로 한정: **충족 / 각사 검토 / N/A / -**. 단서는 그 아래 줄에 괄호로 작게(`(장비 설정)`). 그래도 깨지면 '검토 항목' 열에서 폭을 떼어 결과 열을 넓혀 **한 줄 유지** |
| 8 | 판정 기호를 라틴 `O`·`?` 로 씀 | 도형 없이 텍스트 **`○` / `X`** 만. `O`·`?` 사용 금지 |
| 9 | 3절 제목의 버전 괄호가 본문 제목과 같은 크기·굵기 | 절 제목과 **같은 줄**, 괄호 안은 **작은 글씨·굵기 없음** |
| 10 | 별첨1 전제조건이 다음 줄로 빠지고 문구가 다름 | 제목 끝에 같은 줄로 `(대상명)` 병기 + 이어서 작은 글씨 `※ 전제조건: …`(예: 기업용 계정 기준) |
| 11 | 별첨2 URL 다수 결손 | 각 항목마다 **① 원문 인용(영문은 원문 그대로) → ② 출처 URL 전체 → ③ 캡처** 3종 전부. URL 을 `- (src 미기재)`로 비우는 건 최후 수단이며, `_summary`·캡처 주소창에서 먼저 찾는다 |
| 12 | ①②③ 가 페이지를 걸쳐 텍스트와 캡처가 갈라짐 | 한 항목의 ①②③ 는 **같은 페이지 안에** 오도록 분할 조정 |
| 13 | 표 마지막 한 행만 넘어가 사실상 백지 페이지 발생(별첨3 등) | 페이지 하단이 절반 이상 비거나 잔여 행이 1개면 열폭·이미지 크기·행 분할을 다시 흘려 앞 페이지에 붙인다 |
| 14 | 별첨3·4 를 6열로 자체 설계 | 별첨3·4 표의 **헤더 문구·열 수는 example 의 같은 별첨을 재서 그대로**. 불릿(`- 항목`)+캡처 나열로 대체하지 않고 **가로(landscape) 전폭 표** |
| 15 | 별첨3·4는 가로인데 별첨5 가 다시 세로 | 가로 전환은 **단조** — 별첨3부터 문서 끝까지 가로 유지 |
| 16 | `※ 출처: [별첨 2] 참고` 가 별첨1에만 | 근거를 다른 별첨에 둔 표는 표 아래 마지막 줄에 같은 정형 문구로 참조 표기 |
| 17 | 구성도 하단 글자가 도형 밖으로 넘쳐 겹침 | 구성도 안 텍스트는 박스 안에 들어가는 길이로 줄인다. 넘치면 문구를 줄이지 도형을 겹치지 않는다 |
| 18 | 증적 캡처가 검은 터미널이라 판독 불가 | 캡처는 축소 상태에서 **글자가 읽히는 것**만 채택. 읽히지 않으면 그 항목의 근거는 인용문+URL 로 대체하고 판정을 과장하지 않는다 |

## 3. 골격 (고정)
제목 → 작성일 → 본문 5절 → 종결표기 → 별첨 5종. 표지·목차·로고·개정이력·문서번호·작성자·부서·머리말/꼬리말/페이지번호 없음.
1p 최상단(상단 여백 페이지 1/12 지점) 가운데정렬 제목 — 굵게+밑줄, 본문보다 2~3단계 큼, 밑줄이 글자보다 좌우로 김.

**본문 5절 (재배열·병합·생략·신설 금지)**
1. 배경 — `- ` 하이픈 2줄(도입 사유 / 검토 수행 범위)
2. 서비스 구성 — 구성도 1장만
3. 서비스 개요 (대상 버전 괄호 병기) — 표 2열
4. 보안 기준 — 하이픈 2줄 + 적용 모수 명시 + 표 3열
5. 보안검토 결과 — ① 결론 박스 → ② 건수 요약 한 줄 → ③ 결과표 (순서 엄수)

절 제목은 왼쪽정렬·굵게, 번호는 `1. `. 절 본문은 하이픈 1~2줄로만. 하위번호는 1.1.1까지. 해당 없는 절도 제목을 남기고 '해당 없음'과 사유를 적는다.
5절 결론 박스: 모서리형 테두리, **3줄 이내**, 핵심 결어(활용 가능/조건부 승인 등)만 굵게+밑줄, 페이지 경계에서 쪼개지지 않게 분할.

**서비스 개요 표 6행 (고정, 여기 한 번만)**
회사(제공사·국가·설립연도) / 대상 버전(앱·CLI 등 형태와 버전) / 주요기능 / 동작방식 / 사용모델(소재에 나온 모델명을 세대·등급까지 전부) / 서비스 비용(월 — 개인·상위·팀·기업 플랜).

**별첨 5종 (고정, 여기 한 번만 — 신설 금지)**
[별첨1] 보안검토 결과-상세 / [별첨2] 상세내용 출처 / [별첨3] 서비스 보안 설정 가이드 / [별첨4] 사용 가능 도구 및 통제기능 현황 / [별첨5] 참고.
- 시나리오·이슈마다 새 별첨을 만들지 않고 전부 [별첨1] 상세 표의 '행'으로 흡수. 별첨 제목은 왼쪽정렬·굵게·페이지 최상단.
- [별첨1]: 상세 표 1개 + 표 아래 `※ 출처: [별첨 2] 참고`.
- [별첨2]: 별첨1과 같은 열 구성·같은 순서로 1:1 대응(모수 밖 항목 추가 금지). 각 항목 행 바로 아래 검토항목~비고를 병합한 전폭 행에 ①②③.
- [별첨3]: 관리자 설정 항목별 현재값·권고값 표(+기준 출처). 설정 절차 번호 문단과 대응 캡처는 표 셀 안.
- [별첨4]: 도구 사용기준·통제기능 표.
- [별첨5]: **공개도구 등록 절차 · 관계사 검증방안** 두 주제만. 판정 어휘 정의·재검증 절차·전수 목록 등 다른 주제 금지.
- 별첨 안 단위(시나리오)는 같은 소제목 문구를 같은 순서로 반복: 단위 식별자·개요 → 점검 절차 → 판정 → 판정 근거 → 증적. src 원자료의 단위를 누락하지 않는다.

**종결표기**: 5절 마지막 표 뒤 여러 줄 띄고 오른쪽정렬 `- 이 상 -` (이와 상 사이 공백 정확히 하나, 굵기 없음, 문자 그대로). 뒤로 본문 없음. 별첨은 다음 페이지부터.

## 4. 표·그림 기본값 (example 우선)
- 표 폭 본문 폭 약 90%, **본문 하이픈 글머리보다 안쪽으로** 좌우 들여쓰기, 페이지를 넘어가도 헤더행 반복 없음.
- 열폭 기본값: 3절 15/85 · 4절 20/28/52 · 5절 50/50 · 별첨1 10/45/10/35(구 분 / 검토 항목 / 결과 / 비 고, 단 교정표 #7 적용).
- 헤더 문구는 example 표기(`구 분` / `내 용` / `비 고` 자간 벌림)·음영·가운데굵게 그대로. '구 분' 열의 `(n)` 병기와 세로 병합, 셀 내부 `·` 불릿·줄바꿈 구분도 그대로.
- 구성도: 2절 1장, 가운데정렬, 테두리 없음, 본문폭 85~90%, 그림번호·캡션 없음. 사실대로 작도(사내망/외부망 점선 영역 → 사용자 단말·앱/에이전트 → 경계 프록시 → 외부 엔드포인트).
- 증적 이미지는 본문 0건 — 본문은 '별첨 n 참조'로만. 실물은 별첨 표 **셀 안 임베드** + 아래 가운데정렬 한 줄 캡션(그림번호 없음).

## 5. 문체
개조식 명사형 종결(`…수행`, `…한정`, `…필요함`, `…권고함`). 존댓말 서술 금지(관리자 화면 인용문은 예외).

## 6. 작성 순서와 자체검수
① example 을 페이지 단위로 훑어 '요소 → example 위치' 대응표 작성 → ② `_summary` 를 훑어 개요표 값(버전·모델명·요금)과 판정 근거를 원문 값으로 수집 → ③ 대응표대로 조판 → ④ §2 교정표를 항목 번호대로 훑으며 자기 산출물 대조.

셀 수 있는 것만 검수:
- 제목 문구 = `<대상명> 보안검토 결과`, 날짜 = `YYYY. M.DD`
- 절 5개·문구·순서 / 5절 내부가 결론박스(3줄 이내)→요약 한 줄→결과표
- 요약 어형이 `- 충족(n), 각사 검토 필요(n)` 이고 개수가 별첨1 실제 판정 수와 일치
- 적용 모수 합계 33, 별첨1 항목 33, 별첨2 = 별첨1 과 1:1, 모집단 수치 언급 0건
- 개요표 6행 전부('대상 버전' 독립 행 포함), 빈 값은 `- (src 미기재)`
- 결과표 2열 / 별첨1·2 결과 열에 글자 단위 줄바꿈 0건 / `O`·`?` 기호 0건
- 별첨2 항목 중 URL 결손 수, ①②③ 가 페이지를 걸친 항목 수 — 둘 다 0 목표
- 별첨 정확히 5개, 별첨3·4 헤더·열 수 = example, 별첨3~5 전부 가로
- 구성도 2절 1장 / 본문 증적 이미지 0건 / 캡처는 전부 셀 안 + 한 줄 캡션, 판독 불가 캡처 0건
- 백지·하단 절반 이상 공백 페이지 0, 잔여 1행만 넘어간 페이지 0
- 종결표기 `- 이 상 -` 가 본문 마지막 줄, 그 뒤 본문 없음

## 🔒 엄격 복제(예제 그대로) — 고정 점검항목 카테고리·표 열머리/칸수·종결표기 등은 예제 문구 그대로. 구성도·흐름도는 src 사실로 실제로 그리고, 실제 캡처가 필요한 증적만 [증적] placeholder(증적 날조 금지)
# 보안검토 결과 보고서 생성기 (골격 복사 → 슬롯 채우기)

입력: `{대상 서비스/제품}에 대한 보안성 검토 보고서를 만들라`는 한 줄 요청(예: "workspaces 소재로 예제/기준 형태의 보고서 생성").
할 일은 **아래 골격을 글자 그대로 복사한 뒤 `{ }` 슬롯만 src 실자료로 채워** 완성 보고서(문서 파일)를 만드는 것 하나뿐. 골격의 배치·순서·문구·열 구성은 설명이 아니라 **실제 출력될 문자**다. 골격 밖의 절·표·별첨 신설 금지.

## 0. 불변 3원칙

1. **입력은 딱 3개** — (1) 이 지시문, (2) `src/`(소재 + `src/_srcimg/` 실제 캡처), (3) `example`(예제 형식). 그 밖의 파일·개체 번호·외부 지식·기억 참조 금지.
2. **날조 금지 · 원문 값 그대로** — 버전·모델명·요금·URL·인용문은 src 문자열 그대로. src에 없으면 추정 말고 `- (src 미기재)`. 실제로 캡처하지 않은 화면을 그림·모형·텍스트 모사로 '증적'처럼 제시 금지.
3. **미확인은 `?`** — 조금이라도 확인 안 된 항목은 결과칸 `?`, 비고칸에 무엇이 확인 안 됐는지. 추론으로 판정 메우기 금지. 해당 없음은 `-` + 사유.

값 채우기: `src/_summary` 정리노트에서 **제공사·국가·설립연도·버전 문자열·모델명 전수·요금 문자열·인용문·URL** 수집 → 슬롯에 원문 그대로 이식 → 남은 슬롯은 원자료를 직접 열어 보강 → 그래도 없으면 2번대로 비움.

- 표지·문서번호·작성자·부서 **없음**. 1p 최상단부터 바로 제목.
- 제목: `{대상명} 보안검토 결과` — 가운데 정렬, 굵게+밑줄(밑줄이 글자보다 좌우로 한 칸 더 김), 본문보다 2~3단계 큼. **'보안성 검토'가 아니라 '보안검토'**(5절 제목과 일치).
- 제목 바로 아래 줄: 우측 정렬 날짜 `{YYYY}. {M}.{DD}` 단독 (예: `2026. 8.08`).
- 전 문서 세리프 단일 서체. 밑줄은 **제목과 결론 박스의 핵심 어절 한 곳**에만.
- 전면 개조식(명사형 종결: `~함`, `~필요함`, `~권고함`). 존댓말·서술형 금지(원문 인용 예외).

## 2. 별첨 — 아래 5종 고정, 신설·삭제 금지

시나리오별·이슈별 별첨 신설 금지. 개별 시나리오·실측 케이스는 전부 **[별첨1] 표의 행**으로 흡수.
모든 별첨 표는 **마지막 줄에 `※ 출처: [별첨 2] 참고`**(별첨2는 `※ 출처: 각 항목 URL 참고`) 한 줄.

**[별첨1] 보안검토 결과-상세 ({대상명})** `※ 전제조건 : {계정 tier·네트워크 전제}`
— 부제는 **제목과 같은 줄 뒤에 작은 글씨**로, 문구는 `※ 전제조건 : …` 형식.
4열 `구 분 | 검토 항목 | 결과 | 비 고`, 폭 ≈10:40:12:38.
- **행 수 정확히 33행**, 본문 5절 요약 집계와 산술 일치(세어서 확인).
- 항목번호는 **2단 `대분류.항목`으로 전 구간 통일**(3단 혼용 금지):
  1.1~1.3 서비스 일반(3) / 2.1~2.4 계정·접근통제(4) / 3.1~3.5 데이터 보호(5) / 4.1~4.4 네트워크·모니터링(4) / 5.1~5.4 법무·컴플라이언스(4) / 6.1~6.3 모델 안전(3) → **생성형 AI 23**
  7.1~7.4 실행 통제(4) / 8.1~8.3 도구·확장 거버넌스(3) / 9.1~9.3 감사·통제(3) → **AI Agent 10**
  구분 열에는 그룹명 + `(n)`을 적고 세로 병합.
- 결과 열 어휘는 `충족` / `각사 검토` / `-` / `?` 만. 새 기호(△·PASS·FAIL) 금지, `○`를 라틴 대문자 `O`로 대체 금지. 조건부·단서는 **같은 셀 안 다음 줄에 괄호로 작게**(`각사 검토` ⏎ `(Enterprise 전용)`). 결과 열 폭은 `각사 검토`가 **어절 중간에서 깨지지 않을 만큼** 확보(글자 단위 4~6줄 분해는 실패).
- 비고 열은 **근거 요약(인증명·조항·기능명·수치)만**, 서술 문장 나열 금지.
- 해당 없는 항목도 행 삭제 금지 — 결과 `-`, 비고에 사유.

**[별첨2] 상세내용 출처** — 별첨1과 같은 4열이되 **항목번호 접두 제거**.
각 행에 `① 원문 인용` `② 출처 URL(전체 URL)` `③ 캡처` 3종을 **같은 행**에 묶음(필요 시 검토항목~비고 병합 전폭 행). URL 결손 금지, src에 URL이 없으면 `- (src 미기재)`로 명시. ③ 캡처와 텍스트가 **페이지를 걸쳐 분리되지 않도록** 행 단위로 페이지를 넘긴다.

**[별첨3] 서비스 보안 설정 가이드** / **[별첨4] 사용 가능 도구 및 통제기능 현황**
- 상단 점검 기준 박스: `【 {영역} 검증 항목 】`, 기준 출처는 `[{문서ID}] {가이드명} 中 {항목명}` 형식.
- 본문은 `- {점검 항목}` / `# {판정 문장}` 쌍 목록.
- 설정 절차는 `1)` `2)` 번호 문단 + **그 번호에 대응하는 캡처**.
- 표를 쓰면 별첨1과 동일한 4열 기본, 자체 6열 설계 금지.

**[별첨5] 참고** — `5.1 공개도구 등록 절차` / `5.2 관계사 검증방안` 두 소절 고정.

## 3. 그림·증적

- **사실 도식**(구성도·데이터 흐름도·호출/처리 순서도)은 src만으로 확인되므로 **반드시 실제 작도**. placeholder 대체 금지.
- 그 외 그림은 전부 `src/_srcimg/`의 **실제 캡처**를 별첨 표 셀 안에 임베드(셀 폭 이내 가운데 정렬 + 바로 아래 한 줄 캡션).
- 캡처가 없을 때만 `[증적: 실제 검토 시 삽입]` 을 글자 그대로 두고, 캡션에 **대상 화면·조작·확인 지점**을 명시하며, 그 캡처로만 확정되는 항목의 판정은 `?`.
- 판형: 본문~별첨2는 세로, **별첨3부터 후반 증적 페이지는 가로**로 전환하고 **한 번 가로로 바꾸면 문서 끝까지 가로 유지**(세로 복귀 금지).

## ✍️ 자유 작성(src 실자료로) — 대상의 실제 회사·버전·발견·판정 등 가변 내용(예제 내용 복제 금지)
# ✍️ 자유 작성 영역 — src 실자료로만 채우는 부분
예제의 **형식**만 빌리고 **내용**은 베끼지 않는다. 예제에 적힌 회사·버전·모델·요금·발견·판정 문장을 그대로 옮겨오면 실패다.

## 1. 소재는 src 원문뿐
- 모든 값(회사·국가·설립연도·버전/빌드·모델명·요금·URL·인용문·기능명)은 `src` 원문에서 **그대로** 옮긴다.
- `src/_summary/`를 먼저 훑어 어디에 무엇이 있는지 지도로 삼되, 원자료 접근을 막지 않는다(정리본은 지도일 뿐 근거는 원자료).
- src에 없으면 추정·일반지식·기억으로 채우지 않는다. 빈칸으로 두거나(표에서는 '-'), 무엇이 없어서 비웠는지 근거칸에 쓴다.
- 큰 자료는 통째로 넣지 말고 부분으로 나눠 단계적으로 읽는다(고정 글자수 컷 금지).

## 2. 자유롭게 채우는 항목
- **표1**: 회사(제공사·국가·설립연도) / 주요기능 / 동작방식 / 사용모델(src에 나온 모델명을 세대·등급까지 전부) / 서비스비용(월)(개인·상위·팀·기업 등 플랜별 월 요금 전부). 대상 버전·빌드는 필수 기재이며 3절 제목 괄호에도 같은 값으로 병기한다.
- **1절 배경**: 대상 도입 사유와 이번 검토의 수행 범위.
- **2절 구성도의 내용**: src로 확인된 사실만 박스·화살표로 작도한다(사내망/외부망 경계, 사용자 단말 내 클라이언트 구성요소, 프록시·방화벽 경유선과 그 표기, 사내 로그 서버, 외부 서버·커넥터 연결 등). 확인 안 된 경로는 그리지 않는다.
- **4절 서술 2줄**: 이번 검토가 적용한 기준과 모수를 대상에 맞춰 서술.
- **5절**: 결론 문장, 건수 요약(충족/각사 검토/해당없음 등 실제 집계), 표3의 (기준)·(결과) 서술과 대응 방안.
- **별첨1 결과·비고**: 항목별 판정과 그 근거 요약.
- **별첨2**: 항목별 원문 인용(영문이면 영문 원문 그대로) + 출처 URL + 캡처.
- **별첨3·4**: 대상 제품에서 실제로 존재하는 관리자 설정값·도구 목록·통제 수단과 단기/장기 대책.

## 3. 판정은 실측으로만
- 검증되지 않은 판정을 적지 않는다. 확인 안 된 항목은 '?'로 두고 무엇이 미확인인지 명시한다.
- 판정 근거는 그 문서 안에 증적으로 박혀 있는 것만 근거로 삼는다. '원래 그럼'·외부 기억으로 판정하지 않는다.
- 실측 항목이라도 근거 문서 URL을 함께 적는다. 출처 URL은 반드시 근거 문서의 실제 주소여야 하며 `http://localhost:...` 같은 로컬 주소는 쓰지 않는다.
- 본문 결론의 집계 숫자는 별첨1 행들을 실제로 세어 맞춘다(추정 금지).

## 4. 금지
- 예제의 대상 제품명·회사·버전·모델·요금·발견 내용을 산출물에 남기지 않는다(치환 누락 검수).
- 고정 카테고리에 없는 새 분류를 만들어 자유 내용을 끼워 넣지 않는다.
- src에 존재하는 검토 단위를 누락하지 않는다.

## 5. 자유영역 자체검수
예제 고유명사 잔존 0건 / 표1 다섯 행 모두 src 원문 값 또는 '-' / 버전 표기가 제목 괄호와 표1에서 일치 / 미확인 항목 전부 '?'+미확인 사유 / 별첨2 URL 전부 실제 근거 문서 주소 / 결론 집계와 별첨1 실제 행 집계가 일치.

## 🎨 스타일 — 종결어미·서술 톤·기호/표기·레이아웃 디테일
# 문체·표기 규칙

## 1. 종결어미
- **개조식(명사형 종결)으로 일관한다**: `…확인.` `…제공.` `…필요함.` `…권고함.` `…임.`
- 존댓말·서술형 종결(`…하였습니다` `…합니다` `…됩니다` `…판정하였습니다`)은 전면 금지. 산출물 내 0건이어야 한다.
- 한 문장은 한 사실만 담고 짧게 끊는다. 수식 나열로 늘이지 않는다.

## 2. 서술 톤
- 사실 진술 위주. 홍보·추측·감상 표현을 쓰지 않는다.
- 판정 근거는 '근거 → 판정'의 인과가 드러나게 적되, 표의 비고 열에서는 근거 요약(인증명·조항·기능명)만 짧게 쓰고 여러 문장으로 늘어놓지 않는다.
- 불확실한 것은 확실한 척 쓰지 않는다. 미확인은 미확인이라고 쓴다.

## 3. 강조 표기
- **밑줄은 문서 전체에 딱 2곳**: 제목 1곳 + 결론 박스의 최종 판정 어구 1곳. 그 외 밑줄 금지.
- **굵게**는 제한적으로: 제목 / 절 제목 / 표 헤더행 / 별첨 제목 / 3절 제목의 버전 괄호 / 표3 (결과) 단락의 판정어 / 결론 박스 최종 판정어. 단락이나 셀 전체를 굵게 하지 않는다.
- 색상 강조·형광 표시는 쓰지 않는다.

## 4. 기호·번호 표기
- 절 번호: `1. `(번호 뒤 마침표+공백). 하위번호는 1.1, 1.1.1까지.
- 본문 불릿: `- ` 한 줄 문장. 표 셀 안 불릿: `·` 한 줄씩.
- 개수 표기: 분류명·점검 영역명 뒤에 `(n)`.
- 캡션: 표 위 `<표 n>`, 그림 아래 `<그림 n>`, 문서 전체 통번호.
- 조건부 판정은 `충족 (…별도 검토)`처럼 판정어 뒤 괄호 부기로 적는다.
- 별첨 참조 문구는 `(별첨 n 참고)` 형태로 통일한다.
- 기준 박스 제목은 `【 … 검증 항목 】`, 점검 목록은 `- 점검 항목` / `# 판정 문장` 쌍, 절차는 `1)` `2)` 번호 문단.
- 증적 placeholder 문구는 `[증적: 실제 검토 시 삽입]` 을 글자 그대로 쓴다(임의 변형 금지).

## 5. 날짜·수치·용어 표기
- 작성일: `YYYY. M. D` 형식(점 뒤 공백 1칸, 월·일은 0을 붙이지 않음).
- 버전·요금·모델명은 원문 표기를 그대로 쓴다. 단위·통화 기호를 임의로 바꾸거나 반올림하지 않는다.
- 영문 원문 인용은 번역하지 않고 영문 그대로 옮긴다.
- 같은 대상은 문서 전체에서 같은 명칭으로 부른다(약칭을 섞지 않는다).

## 6. 조판
- 글꼴: 한글 명조 계열 + 영문 세리프. 줄간격은 넉넉하게.
- 제목은 본문보다 2~3단계 큰 크기.
- 정렬: 제목 가운데, 작성일 오른쪽, 절 제목·별첨 제목 왼쪽, 표·그림 가운데, 종결표기 오른쪽.

## 7. 표기 자체검수
밑줄 정확히 2곳 / 존댓말 종결 0건 / 굵게가 허용 위치 밖에 없음 / 본문 불릿 `- `·셀 불릿 `·` 혼용 없음 / 날짜 형식 일치 / 캡션 위치와 통번호 연속 / placeholder 문구 정확히 일치 / 명칭 표기 일관.
