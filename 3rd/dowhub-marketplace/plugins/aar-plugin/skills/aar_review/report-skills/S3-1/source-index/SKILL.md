# 소재 정리 (_summary) 규약

원자료(`workspaces/`)는 시나리오·항목 폴더 수십 개에 스크린샷 수백 장까지 있어 **매번 전부 읽으면 토큰이 감당이 안 된다.**
그래서 **맨 처음 한 번만** 정리해 두고, 그 뒤로는 정리본만 읽는다.

## 절차

1. **`workspaces/_summary/` 가 있으면 → 만들지 말고 그것을 쓴다.**
   - `_summary/INDEX.md` 를 Read 해 단위 목록과 각 단위가 무엇인지 파악
   - 필요한 단위의 `_summary/<단위>.md` 를 Read 해 내용을 가져온다
   - 정리노트로 부족할 때만 그 단위의 원자료를 직접 Read

2. **없으면 → 만든다(1회).** `workspaces/` 바로 아래 하위폴더 = 단위. 단위마다:
   - 그 폴더의 자료를 **직접 다 읽는다**(report.json·md·html, 그리고 `img/` 의 스크린샷도 Read 로 **실제로 보고**)
   - 아래 형식으로 `workspaces/_summary/<단위>.md` 저장
   - 전부 끝나면 `workspaces/_summary/INDEX.md` 에 `- \`_summary/<단위>.md\` — **<단위>** : 한 줄 설명` 목록 저장

## 정리노트에 담을 것 (`_summary/<단위>.md`)

- **제목/주제** — 이 단위가 무엇을 다루는지 1~2줄
- **구조·아키텍처** — 등장하는 구성요소(클라이언트·프록시·데몬·저장소·외부연동 등)와 관계, 버전·식별자
- **판정/결과와 근거** — 무엇을 어떻게 확인했고 결과가 무엇인지. 수치·설정값·경로·식별자는 **원문 그대로**
- **🖼️ 이미지(OCR)** — `파일명 — 화면에 보이는 것(핵심 텍스트·수치 그대로)` 를 한 줄씩.
  화면 속 명령어·로그·설정값은 **읽은 그대로** 적는다
- **원본 경로** — 더 자세히 봐야 할 때 읽을 파일들의 실제 경로

## 규칙

- 🚨 **지어내기 금지** — 자료에 없는 건 쓰지 않는다. 요약하되 **사실·수치·문구는 보존**한다.
- 🚨 이미 `_summary/<단위>.md` 가 있으면 그 단위는 **건너뛴다**(다시 만들지 않는다).
- 정리노트는 원자료를 대신할 만큼 충실해야 한다 — 나중에 이것만 보고 문서를 쓴다.
