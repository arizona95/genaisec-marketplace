## 📐 문서 구조 — 섹션 순서·제목·번호, 표/그림이 어디 위치하는지, 별첨 구성(뼈대)
# 문서 뼈대 (배치·순서 전담 — 고정 문구 strict, 채울 내용 free, 표기·문체 style)

## 0. 참조 입력 (불변) · 값 원칙
- 참조 경로는 셋뿐: ① 이 skill 폴더 안 로컬 파일 ② `src/`(실자료 + `src/_srcimg/` 실제 캡처 + `src/_summary/` 정리노트) ③ `example/`(서식 기준 예제). 그 밖의 파일·다른 산출물·개체 번호(후보 번호 등)는 열지도 언급하지도 않는다. 피드백에 번호가 나와도 번호는 쓰지 말고 '무엇이 왜 좋았는지'만 일반 원리로 적용한다.
- **날조 금지(전 절 공통):** 버전·모델명·요금·URL·인용문·수치는 `src`(우선 `_summary`) 원문 값 그대로. 소재에 없으면 추정하지 말고 `- (src 미기재)`로 비운다. 증적은 `_srcimg` 실제 캡처만 — placeholder·가공 이미지 금지.

## 1. 🔑 시각 세부는 서술하지 말고 example 을 가리킨다 (1차 규칙)
정렬·여백·열폭·표 폭·들여쓰기·글자 크기 단계·테두리·음영·자간·캡션 유무와 위치·줄간·이미지 크기는 문장으로 판단하지 않는다. 매 요소(제목/날짜/절 본문/표 n/구성도/결론 박스/종결표기/별첨 k)마다:
1. example 의 같은 위치를 연다.
2. 그 값을 눈으로 재서 그대로 복제한다(열폭 비율, 표 폭과 좌우 들여쓰기, 헤더행 음영·굵기·자간, 본문 대비 제목 크기 단계, 캡션 유무·위치·정렬).
3. example 에 **없는 요소는 추가하지 않는다** — 표 캡션(`<표 n>`)이 example 에 없으면 붙이지 않고, `【 … 】` 장식 박스·자체 소제목·요약 절도 신설 금지.
4. example 에서 재기 어려운 것만 §2~§6 명시값을 따른다. 충돌 시 **example 우선**.

## 2. 페이지 흐름 (고정)
제목 → 작성일 → 본문 5절 → 종결표기 → 별첨 5종.
- 표지·목차·로고·개정이력·문서번호·작성자·부서·머리말·꼬리말·페이지번호: 두지 않는다.
- 1p 최상단(상단 여백 페이지 1/12 지점) 가운데정렬 제목 — 굵게+밑줄, 본문보다 2~3단계 큼, 밑줄이 글자보다 좌우로 김. 바로 아래 오른쪽정렬로 작성일만, 표기는 `YYYY. M.DD`(일 2자리).
- 백지 페이지·캡션 없는 캡처 단독 페이지 금지. 페이지 하단이 절반 이상 비면 열폭·이미지 크기·분할을 다시 흘려 example 밀도에 맞춘다.

## 3. 본문 절 구성 (5절 고정 — 재배열·병합·생략·신설 금지)
1. 배경 — `- ` 하이픈 2줄(도입 사유 / 검토 수행 범위)
2. 서비스 구성 — 구성도 1장만
3. 서비스 개요 (대상 버전 괄호 병기) — 표: 2열
4. 보안 기준 — 하이픈 2줄 + 모수 명시 + 표: 3열
5. 보안검토 결과 — ① 결론 박스 → ② 건수 요약 한 줄 → ③ 결과표 (순서 엄수)
- 절 제목은 왼쪽정렬·굵게, 번호는 `1. ` 형식. 절 본문은 하이픈 1~2줄로만. 하위번호는 1.1.1까지.
- 3절 제목의 버전 괄호는 제목과 같은 줄(표 위 별도 줄로 떼지 않음).
- 해당 사항 없는 절도 제목을 남기고 본문에 '해당 없음'과 사유를 적는다.
- **모수 체계는 예제 그대로(자체 분류·'서비스별 특화항목' 신설 금지):** 모집단은 외부 생성형 AI 점검항목 34개 + SaaS형 AI Agent 점검항목 20개, 이 중 **적용 모수 = 생성형 AI 23 + AI Agent 10 = 33개**(합계 33, 34 로 늘리지 않음). 영역 구분·항목 번호·항목명은 example 코드 체계를 그대로 승계.
- **서비스 개요 표 행 목록(고정, 여기 한 번만):** 회사(제공사·국가·설립연도) / 대상 버전(앱·CLI 등 형태와 버전) / 주요기능 / 동작방식 / 사용모델(소재에 나온 모델명을 세대·등급까지 전부) / 서비스 비용(월 — 개인·상위·팀·기업 플랜). '대상 버전'은 3절 제목 괄호와 중복돼도 **독립 행으로 반드시 존재**.
- 5절 결론 박스: 모서리형 테두리, 본문 **3줄 이내**, 핵심 결어(예: 활용 가능/조건부 승인)만 굵게+밑줄, 페이지 경계에서 쪼개지지 않게 분할 조정.
- 5절 요약 한 줄: 하이픈 한 줄로 `- 충족(n), 각사 검토 필요(n)` 어형 유지. 자체 판정어(미충족·미확인 등)를 늘려 어형을 바꾸지 않는다.

## 4. 표·그림의 자리 (수치는 example 우선, 아래는 기본값)
- 표 폭은 본문 폭 약 90%, **본문 하이픈 글머리보다 안쪽으로** 좌우 들여쓰기, 가운데 정렬, 페이지를 넘어가도 헤더행 반복 인쇄 없음.
- 열폭 기본값: 3절 개요표 15/85 · 4절 기준표 20/28/52 · 5절 결과표 2열 50/50(상세내용 / 대응 방안) · 별첨1 4열 10/45/10/35(구 분 / 검토 항목 / 결과 / 비 고). 결과표에 '구 분' 열을 덧붙여 3·4열로 만들지 않는다.
- 헤더 문구는 example 표기(`구 분` / `내 용` / `비 고` 처럼 자간 벌림)와 음영·가운데굵게 그대로. '구 분' 열의 `(n)` 병기와 세로 병합, 셀 내부 `·` 불릿·줄바꿈 구분, 결과 열의 짧은 어절(충족 / N/A / - / 각사 검토)과 단서 괄호(예: `(장비 설정)`)도 그대로.
- 판정 기호는 도형 없이 텍스트 `○ / X`.
- 구성도: 2절에 1장, 가운데정렬, 테두리 없음, 본문폭 85~90%, 그림번호·캡션 없음. 박스·화살표로 사실대로 작도(사내망/외부망 점선 영역 구분 → 사용자 단말·앱/에이전트 → 경계 프록시 → 외부 엔드포인트 흐름).
- 증적 이미지는 본문에 0건 — 본문에서는 '별첨 n 참조'로만 가리키고, 실물은 별첨 표의 **셀 안에 임베드** + 그 아래 가운데정렬 한 줄 캡션(그림번호 없음, 축소 상태에서도 판독 가능한 크기).

## 5. 종결표기의 자리
- 본문 5절 마지막 표가 끝난 뒤 여러 줄 띄고 오른쪽정렬로 `- 이 상 -` — 이와 상 사이 공백 정확히 하나, 굵기 없음, 문자 그대로.
- 뒤로 본문이 이어지지 않는다. 별첨은 다음 페이지부터 별도 장으로 시작.

## 6. 별첨 구성 (정확히 5종 고정 — 신설 금지, 목록은 여기 한 번만)
[별첨1] 보안검토 결과-상세 / [별첨2] 상세내용 출처 / [별첨3] 서비스 보안 설정 가이드 / [별첨4] 사용 가능 도구 및 통제기능 현황 / [별첨5] 참고.
- 시나리오·이슈마다 새 별첨을 만들지 않고, 개별 시나리오는 전부 [별첨1] 상세 표의 '행'으로 흡수.
- 별첨 제목은 왼쪽정렬·굵게·페이지 최상단.
- [별첨1]: 제목에 `(대상명)` 병기 + 뒤에 작은 글씨로 전제조건(예: 기업용 계정 기준) 한 구절. 상세 표 1개 + 표 아래 마지막 줄에 정형 문구 `※ 출처: [별첨 2] 참고`.
- [별첨2]: 별첨1과 같은 열 구성·같은 항목 순서로 **1:1 대응**(모수 밖 항목 추가 금지). 각 항목 행 **바로 아래** 검토항목~비고를 병합한 전폭 행을 두고 그 안에 ① 원문 인용(영문은 원문 그대로) → ② 출처 URL → ③ 캡처 순서.
- [별첨3]·[별첨4]: 가로(landscape) 전환 + **표 기반**, 표가 페이지 폭 전체를 채우게 하고 표 없는 불릿(`- 항목` / `# 서술`)+캡처 나열로 대체하지 않는다. 별첨3 = 관리자 설정 항목별 현재값·권고값 표(+기준 출처 표기, 설정 절차 번호 문단과 각 번호에 대응하는 캡처는 표 셀 안). 별첨4 = 도구 사용기준·통제기능 표(열 수는 example 그대로, 6열).
- [별첨5]: **공개도구 등록 절차 · 관계사 검증방안**. 판정 어휘 정의·재검증 절차·자체 검토단위 전수 목록 같은 다른 주제를 붙이지 않는다.

## 7. 별첨 안의 단위(시나리오) 반복 템플릿
단위마다 같은 소제목 문구를 같은 순서로 반복: 단위 식별자·개요 → 점검 절차 → 판정 → 판정 근거 → 증적. 항목 가감 없이, src 원자료의 단위를 누락하지 않는다.

## 8. 문체
개조식 명사형 종결(`…수행`, `…한정`, `…필요함`, `…권고함`). 존댓말 서술 금지(관리자 화면 인용문은 예외).

## 9. 컴팩트
최대한 덜어낸 것이 좋은 산출물이다. 고정 목록(별첨 5종·모수 33·개요표 행 목록·종결표기)은 한 곳에 한 번만 적고 다른 절에서는 참조만. 임의 추가 절·잉여 별첨·중복 서술 금지.

## 10. 작성 순서와 배치 자체검수
작성 순서: ① example 을 페이지 단위로 훑어 '요소 → example 위치' 대응표 작성 → ② `_summary` 를 훑어 개요표 값(버전·모델명·요금)과 판정 근거를 원문 값으로 수집 → ③ 대응표대로 조판.
검수(셀 수 있는 것만):
- 절 5개·문구·순서 일치 / 5절 내부가 결론박스(3줄 이내)→요약 한 줄→결과표
- 열폭·표 폭·들여쓰기·캡션 유무가 example 의 같은 위치와 일치 / example 에 없는 요소 0건
- 적용 모수 합계 = 33, 별첨1 항목 수 = 33, 별첨2 항목 = 별첨1 과 1:1
- 개요표 6행 전부 존재('대상 버전' 독립 행 포함), 빈 값은 `- (src 미기재)`
- 구성도 2절 1장 / 본문 증적 이미지 0건 / 캡처는 전부 표 셀 안 + 한 줄 캡션
- 별첨 정확히 5개, 별첨3·4 가로 페이지이며 전폭 표 존재
- 백지 0, 하단 절반 이상 공백 페이지 0
- 종결표기가 `- 이 상 -` 이며 본문 마지막 줄, 그 뒤 본문 없음

## 🔒 엄격 복제(예제 그대로) — 고정 점검항목 카테고리·표 열머리/칸수·종결표기 등은 예제 문구 그대로. 구성도·흐름도는 src 사실로 실제로 그리고, 실제 캡처가 필요한 증적만 [증적] placeholder(증적 날조 금지)
# 스킬: `<대상명> 보안검토 결과` 보고서 생성

## 0. 입력은 3개뿐 (불변)
**(1) 이 스킬 폴더 로컬 파일 / (2) src(정리노트 `_summary`·원자료·`src/_srcimg` 증적 캡처) / (3) example(예제 형식)** 셋만 본다. 그 밖의 파일·개체 번호·외부 지식·기억 참조 금지.
- **형식**(외형·절 구성·표 열·별첨 종류·모수 체계·문체·종결표기)은 example 을 글자 그대로 복제. 지침과 예제 실물이 갈리면 **예제 실물이 기준**.
- **내용**(회사·버전·모델·요금·실측 판정·근거)은 예제를 베끼지 말고 src 실자료로만 채운다.

## 1. 공통 원칙 (이후 절은 이 절을 따른다)
1. **날조 금지.** 확인 안 된 값·화면·근거를 만들지 않는다. 캡처하지 않은 화면을 그림·모형·텍스트 모사로 '증적'처럼 제시하지 않는다.
2. **원문 값 그대로.** 버전 문자열·모델명·요금·인용문은 src 표기 그대로. 추정·일반지식 금지.
3. **빈칸 0건.** 값 없으면 `-`, src 에 없으면 `- (src 미기재)`, 대상에 해당 없으면 `-` + 사유를 근거칸에.
4. **미확인은 `?`.** 조금이라도 확인 안 됐으면 `?` + 무엇이 왜 미확인인지 근거칸에 완결 문장으로. 추론으로 판정을 메우지 않는다.
5. **자체완결.** 문서 안에 인용문·URL·캡처로 박혀 있지 않은 근거로는 판정을 적지 않는다.
6. **개조식 명사형 종결**(`~함`, `~필요함`, `~권고함`, `~미검증`). 존댓말·서술형 금지(원문 인용은 예외).

## 2. 문서 외형 (고정)
- 1p 최상단 **가운데 정렬 제목** `<대상명> 보안검토 결과` — 굵게+밑줄, 밑줄이 글자보다 좌우로 한 칸 더 길게, 본문보다 2단계 큼. **'보안성 검토'가 아니라 '보안검토'**(5절 제목과 동일 문구).
- 제목 바로 아래 줄 **우측 정렬 날짜만** `YYYY. M.DD`(예: `2026. 8.08`).
- 문서번호·작성자·부서·기관명·표지 페이지 **없음**.
- 전 문서 세리프 단일 서체, 자간 좁힘. **밑줄은 제목과 결론 박스 핵심 어절(예: 조건부 승인) 두 곳에만.**
- 본문(1~5절) 세로 판형, **별첨 후반 증적 페이지부터만 가로로 전환하고 되돌리지 않는다**(단조 전환).
- 본문 마지막 줄 우측 정렬 `- 이 상 -` — 하이픈·공백1·이·공백1·상·공백1·하이픈, 굵기 없음, 자간 벌리지 않음. 이후 별첨은 **새 페이지** 시작.

## 3. 절 구성 (5절 고정 — 각 절은 아래 질문 한 줄에만 답한다)
| 절 | 그 절이 답해야 할 질문 |
|---|---|
| 1. 배경 | 왜 검토했나 |
| 2. 서비스 구성 | 무엇으로 구성되나 (→ 구성도 1개) |
| 3. 서비스 개요 | 무엇을 쓰는가 (→ 표1) |
| 4. 보안 기준 | 무엇으로 판단했나 (→ 표2) |
| 5. 보안검토 결과 | 써도 되는가 (→ 결론 박스 → 한 줄 요약 → 표3) |

절 제목은 위 문구·순서 그대로(가감·개명·번역 금지), 좌측 정렬 굵게 본문보다 1단계 큼. 절 본문은 `- ` 하이픈 글머리, 나머지는 표·그림이 담당. 3절 제목 뒤 버전 병기는 **괄호 안 작은 글씨**.
5절 블록 순서 고정: ① 테두리 박스 1개·음영 없음·**3줄 이내** 결론 → ② `- 충족(n), 각사 검토 필요(n)` **한 줄 요약(이 두 항목만, 제3항목 금지)** → ③ 표3.

## 4. 고정 모수: 생성형 AI 23 + AI Agent 10 = 총 33개
자체 분류 신설·개명·번역·재정렬·증감 **금지**. 예제에 없는 모집단 수치 계층(“외부 생성형 AI 34개 / SaaS형 AI Agent 20개” 같은 원 모집단 표현) 추가 금지.

| 구분 | 점검 영역 (개수) |
|---|---|
| 생성형 AI (23) | 서비스 일반 (3) / 계정·접근통제 (4) / 데이터 보호 (5) / 네트워크·모니터링 (4) / 법무·컴플라이언스 (4) / 모델 안전 (3) |
| AI Agent (10) | 실행 통제 (4) / 도구·확장 거버넌스 (3) / 감사·통제 (3) |

대상 고유 실측 내용이 이 카테고리에 안 들어가면 **기존 항목의 비고·증적으로 흡수**. 해당 없는 카테고리도 행을 지우지 않고 `-` + 사유로 남긴다. 항목번호는 예제 체계를 따르되 **문서 전 구간 자릿수 형식 통일**(2단·3단 혼용 금지).

## 5. 판정 어휘 (예제 집합만)
- 결과 열: **충족 / 각사 검토 필요 / ? / -**. 조건부는 괄호 부기(예: `각사 검토 필요 (Enterprise 전용)`).
- 예·아니오 셀: **`○`(U+25CB) / `X`**. 라틴 대문자 `O` 금지.
- `△`·PASS·FAIL 등 새 기호 금지.

## 6. 표 규격 (공통 + 표별)
**공통** — 전 셀 실선 테두리, 헤더행만 회색 음영+굵게+가운데정렬, 데이터 셀 좌측정렬(구분 열은 가운데), 셀 내부는 `·` 불릿 한 줄씩. 헤더 문구 자간 벌림 `구 분` / `내 용` / `비 고`. 좌측 구분 열은 **반드시 세로 병합**(행마다 분류명 반복 인쇄는 실패)하고 아래에 개수 병기. 표는 본문 하이픈보다 안쪽 들여쓰기, 본문 폭 ≈90%. 열 머리 텍스트·열 개수·열 순서·병합 구조를 예제와 동일하게 유지(열 가감 금지).

- **표1 (3절 서비스 개요)** — 2열 `구 분 | 내 용`, 폭 ≈15:85. 행 목록·순서 고정(가감 금지):
  **회사**(제공사·국가·설립연도) / **대상 버전**(앱·CLI 등 형태별 버전 문자열) / **주요기능** / **동작방식** / **사용모델**(src 에 나온 모델명을 세대·등급까지 전부 나열 + alias + 실측 요청 본문 `model` 값) / **서비스 비용(월)**(개인·상위·팀·기업 플랜 요금).
  채우는 절차: `_summary` 를 먼저 훑어 버전·모델명·요금 문자열을 원문 값 그대로 옮기고, 없으면 §1-3 표기.
- **표2 (4절 보안 기준)** — 3열 `구 분 | 점검 영역 | 주요 점검 내용`, 폭 ≈20:28:52. 구분 열에 §4 두 대분류 모두 존재, 점검 영역명 뒤 `(n)` 병기.
- **표3 (5절 보안검토 결과)** — 예제 실물 열 구성 그대로(`상세내용 | 대응 방안` 50:50). 분류열 유무를 임의로 바꾸지 않는다(있으면 세로 병합). 상세내용 셀은 반드시 두 단락 `(기준) …` / `(결과) …`. 별첨 참조는 대응 방안 셀 끝에 `(별첨 n 참고)` 로 붙이고 내용에 맞는 번호로 분산(전부 같은 번호 금지, 한 셀 중복 출력 금지).

## 7. 별첨은 아래 5종 고정 — 신설 금지
시나리오·이슈별 새 별첨을 만들지 않는다. 개별 시나리오는 **[별첨1] 표의 행으로 흡수**.

1. **[별첨1] 보안검토 결과-상세** — 4열 `구 분 | 검토 항목 | 결과 | 비 고`, 폭 ≈10:45:10:35. 제목 **같은 줄 뒤 작은 글씨**로 `※ 전제조건 …`(전제 계정 tier·네트워크 조건). **행 수 = 33 이고 본문 5절 요약 집계와 산술이 정확히 일치**. 비고 열은 근거 요약(인증명·조항·기능명)만, 서술 문장 나열 금지.
2. **[별첨2] 상세내용 출처** — 별첨1과 같은 4열 구성이되 항목번호 접두 제거. 각 근거를 **① 원문 인용 ② 출처 전체 URL ③ 캡처** 3종으로 묶어 전폭 병합 행에 담는다. **URL 은 결손 없이 전부 채우고**, src 에 없으면 `- (src 미기재)`.
3. **[별첨3] 서비스 보안 설정 가이드**
4. **[별첨4] 사용 가능 도구 및 통제기능 현황**
   3·4는 상단에 `【 … 검증 항목 】` 점검 기준 박스(기준 출처는 `[문서ID] <가이드명> 中 <항목명>` 형식), 본문은 `- 점검 항목` / `# 판정 문장` 쌍 목록, 설정 절차는 `1)` `2)` 번호 문단과 그 번호에 대응하는 캡처.
5. **[별첨5] 참고** — `5.1 공개도구 등록 절차` / `5.2 관계사 검증방안`.

**모든 별첨 표 아래 마지막 줄에 출처 안내 한 줄**(`※ 출처: [별첨 n] 참고`) — 별첨1 에만 넣고 3·4·5 에서 빠뜨리지 않는다.

## 8. 그림
- **사실 도식은 실제로 그린다.** 본문 그림은 **2절 구성도 1개**: 사내망/외부망을 점선 영역으로 나누고 사용자 단말 구성요소 → 경계 프록시(TLS 복호) → 외부 엔드포인트를 박스·화살표로 잇는 데이터 흐름도. 폭 ≈85%, 가운데 정렬, 바깥 테두리 없음. 도형 밖으로 글자가 넘쳐 겹치지 않게 한다.
- 나머지 그림은 전부 **별첨 표 셀 안의 실제 캡처**(`src/_srcimg`)이며 셀 폭 이내 가운데 정렬 + 바로 아래 한 줄 캡션. 판독 가능한 캡처를 고른다(전면 검은 터미널 화면은 근거로 쓰지 않는다).
- 실제 캡처가 있어야만 성립하는 증적(콘솔·설정 화면·응답·로그)에 캡처가 **없을 때만** `[증적: 실제 검토 시 삽입]` 을 글자 그대로 두고, 캡션에 무엇을 어디서 어떤 조작으로 캡처해야 하는지 명시하며, **그 항목의 판정은 `?`**.

## 9. 조판 (예제 밀도 유지)
- **결과 열은 짧은 어절 하나**만, 단서는 아래 줄에 괄호로 작게. `각사 검 / 토` 처럼 어절이 글자 단위로 쪼개지면 열폭을 늘려 해결.
- 표의 마지막 한 행만 다음 페이지로 넘어가 **사실상 공백 페이지**가 생기지 않게 행을 붙여 둔다.
- 별첨2 의 인용·URL·캡처 3종이 **같은 페이지 안 같은 행**에 보이게 한다(페이지 걸침 금지).

## ✍️ 자유 작성(src 실자료로) — 대상의 실제 회사·버전·발견·판정 등 가변 내용(예제 내용 복제 금지)
# ✍️ 자유 작성 영역 — src 실자료로만 채우는 부분
예제의 **형식**만 빌리고 **내용**은 베끼지 않는다. 예제에 적힌 회사·버전·모델·요금·발견·판정 문장을 그대로 옮겨오면 실패다.

## 1. 소재는 src 원문뿐
- 모든 값(회사·국가·설립연도·버전/빌드·모델명·요금·URL·인용문·기능명)은 `src` 원문에서 **그대로** 옮긴다.
- `src/_summary/`를 먼저 훑어 어디에 무엇이 있는지 지도로 삼되, 원자료 접근을 막지 않는다(정리본은 지도일 뿐 근거는 원자료).
- src에 없으면 추정·일반지식·기억으로 채우지 않는다. 빈칸으로 두거나(표에서는 '-'), 무엇이 없어서 비웠는지 근거칸에 쓴다.
- 큰 자료는 통째로 넣지 말고 부분으로 나눠 단계적으로 읽는다(고정 글자수 컷 금지).

## 2. 자유롭게 채우는 항목
- **표1**: 회사(제공사·국가·설립연도) / 주요기능 / 동작방식 / 사용모델(src에 나온 모델명을 세대·등급까지 전부) / 서비스비용(월)(개인·상위·팀·기업 등 플랜별 월 요금 전부). 대상 버전·빌드는 필수 기재이며 3절 제목 괄호에도 같은 값으로 병기한다.
- **1절 배경**: 대상 도입 사유와 이번 검토의 수행 범위.
- **2절 구성도의 내용**: src로 확인된 사실만 박스·화살표로 작도한다(사내망/외부망 경계, 사용자 단말 내 클라이언트 구성요소, 프록시·방화벽 경유선과 그 표기, 사내 로그 서버, 외부 서버·커넥터 연결 등). 확인 안 된 경로는 그리지 않는다.
- **4절 서술 2줄**: 이번 검토가 적용한 기준과 모수를 대상에 맞춰 서술.
- **5절**: 결론 문장, 건수 요약(충족/각사 검토/해당없음 등 실제 집계), 표3의 (기준)·(결과) 서술과 대응 방안.
- **별첨1 결과·비고**: 항목별 판정과 그 근거 요약.
- **별첨2**: 항목별 원문 인용(영문이면 영문 원문 그대로) + 출처 URL + 캡처.
- **별첨3·4**: 대상 제품에서 실제로 존재하는 관리자 설정값·도구 목록·통제 수단과 단기/장기 대책.

## 3. 판정은 실측으로만
- 검증되지 않은 판정을 적지 않는다. 확인 안 된 항목은 '?'로 두고 무엇이 미확인인지 명시한다.
- 판정 근거는 그 문서 안에 증적으로 박혀 있는 것만 근거로 삼는다. '원래 그럼'·외부 기억으로 판정하지 않는다.
- 실측 항목이라도 근거 문서 URL을 함께 적는다. 출처 URL은 반드시 근거 문서의 실제 주소여야 하며 `http://localhost:...` 같은 로컬 주소는 쓰지 않는다.
- 본문 결론의 집계 숫자는 별첨1 행들을 실제로 세어 맞춘다(추정 금지).

## 4. 금지
- 예제의 대상 제품명·회사·버전·모델·요금·발견 내용을 산출물에 남기지 않는다(치환 누락 검수).
- 고정 카테고리에 없는 새 분류를 만들어 자유 내용을 끼워 넣지 않는다.
- src에 존재하는 검토 단위를 누락하지 않는다.

## 5. 자유영역 자체검수
예제 고유명사 잔존 0건 / 표1 다섯 행 모두 src 원문 값 또는 '-' / 버전 표기가 제목 괄호와 표1에서 일치 / 미확인 항목 전부 '?'+미확인 사유 / 별첨2 URL 전부 실제 근거 문서 주소 / 결론 집계와 별첨1 실제 행 집계가 일치.

# 문체·표기 규칙

## 1. 종결어미
- **개조식(명사형 종결)으로 일관한다**: `…확인.` `…제공.` `…필요함.` `…권고함.` `…임.`
- 존댓말·서술형 종결(`…하였습니다` `…합니다` `…됩니다` `…판정하였습니다`)은 전면 금지. 산출물 내 0건이어야 한다.
- 한 문장은 한 사실만 담고 짧게 끊는다. 수식 나열로 늘이지 않는다.

## 2. 서술 톤
- 사실 진술 위주. 홍보·추측·감상 표현을 쓰지 않는다.
- 판정 근거는 '근거 → 판정'의 인과가 드러나게 적되, 표의 비고 열에서는 근거 요약(인증명·조항·기능명)만 짧게 쓰고 여러 문장으로 늘어놓지 않는다.
- 불확실한 것은 확실한 척 쓰지 않는다. 미확인은 미확인이라고 쓴다.

## 3. 강조 표기
- **밑줄은 문서 전체에 딱 2곳**: 제목 1곳 + 결론 박스의 최종 판정 어구 1곳. 그 외 밑줄 금지.
- **굵게**는 제한적으로: 제목 / 절 제목 / 표 헤더행 / 별첨 제목 / 3절 제목의 버전 괄호 / 표3 (결과) 단락의 판정어 / 결론 박스 최종 판정어. 단락이나 셀 전체를 굵게 하지 않는다.
- 색상 강조·형광 표시는 쓰지 않는다.

## 4. 기호·번호 표기
- 절 번호: `1. `(번호 뒤 마침표+공백). 하위번호는 1.1, 1.1.1까지.
- 본문 불릿: `- ` 한 줄 문장. 표 셀 안 불릿: `·` 한 줄씩.
- 개수 표기: 분류명·점검 영역명 뒤에 `(n)`.
- 캡션: 표 위 `<표 n>`, 그림 아래 `<그림 n>`, 문서 전체 통번호.
- 조건부 판정은 `충족 (…별도 검토)`처럼 판정어 뒤 괄호 부기로 적는다.
- 별첨 참조 문구는 `(별첨 n 참고)` 형태로 통일한다.
- 기준 박스 제목은 `【 … 검증 항목 】`, 점검 목록은 `- 점검 항목` / `# 판정 문장` 쌍, 절차는 `1)` `2)` 번호 문단.
- 증적 placeholder 문구는 `[증적: 실제 검토 시 삽입]` 을 글자 그대로 쓴다(임의 변형 금지).

## 5. 날짜·수치·용어 표기
- 작성일: `YYYY. M. D` 형식(점 뒤 공백 1칸, 월·일은 0을 붙이지 않음).
- 버전·요금·모델명은 원문 표기를 그대로 쓴다. 단위·통화 기호를 임의로 바꾸거나 반올림하지 않는다.
- 영문 원문 인용은 번역하지 않고 영문 그대로 옮긴다.
- 같은 대상은 문서 전체에서 같은 명칭으로 부른다(약칭을 섞지 않는다).

## 6. 조판
- 글꼴: 한글 명조 계열 + 영문 세리프. 줄간격은 넉넉하게.
- 제목은 본문보다 2~3단계 큰 크기.
- 정렬: 제목 가운데, 작성일 오른쪽, 절 제목·별첨 제목 왼쪽, 표·그림 가운데, 종결표기 오른쪽.

## 7. 표기 자체검수
밑줄 정확히 2곳 / 존댓말 종결 0건 / 굵게가 허용 위치 밖에 없음 / 본문 불릿 `- `·셀 불릿 `·` 혼용 없음 / 날짜 형식 일치 / 캡션 위치와 통번호 연속 / placeholder 문구 정확히 일치 / 명칭 표기 일관.
