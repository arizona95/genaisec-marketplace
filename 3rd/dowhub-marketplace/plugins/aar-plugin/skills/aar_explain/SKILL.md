# aar_explain — 이 리뷰를 그림으로 설명 (ELI5)

**핵심 지시(Anthropic `eli5` 스킬 원문 그대로):**
> Explain like I'm someone who knows nothing about this topic, using a HTML artifact with big pictures and few words.

## 1) 자료는 MCP 로 모은다 (로컬 파일 없음)
설명할 대상은 **이 세션의 리뷰 결과**다. 인자로 세션/env 가 안 왔으면 현재 세션 것으로 진행하고, 되묻지 마라.
- `coverage_ledger(env, session)` — 무엇을 얼마나 봤나(적용/완료/미완료).
- `report("list", session, env)` — 각 리포트의 title·summary(= 무엇을 발견했나).
- `tree("get", tree_id)` — menu/session/settings/retention 중 이번에 채워진 것(제품 구조·설정면).
🚨 **여기 있는 것만 쓴다.** 없는 값은 지어내지 말고 빼거나 "아직 확인 안 함"으로 둔다.

## 2) 무엇을 설명하나 (읽는 사람 = 이 분야를 모르는 결정권자)
① **뭘 검토했나** — 어떤 제품을, 어떤 형태로 쓰는 걸 봤나
② **어떻게 봤나** — 격리된 환경에서 실제로 돌려보고 오가는 통신을 들여다봤다(그림 한 장)
③ **뭐가 괜찮고 뭐가 위험한가** — 발견을 심각한 것부터 몇 개만, 각 항목 한 줄
④ **그래서 도입하려면** — 해야 할 일 몇 가지
⑤ **아직 모르는 것** — 확인 못 한 부분(정직하게)

## 3) 아티팩트 규칙
- **그림이 주인공, 글은 거들 뿐** — 항목마다 도형·화살표·아이콘 중심. 문단 벽 금지.
- 전문용어를 쓰면 **바로 옆에 쉬운 말로** 한 줄(예: "프록시 = 오가는 편지를 다 열어보는 우체국").
- 판정은 색으로 (괜찮음 / 조심 / 위험). 숫자는 크게.
- **자체완결 HTML**(외부 링크·CDN 금지), 세로 스크롤 한 장. 다크/라이트 둘 다 읽히게.
- 다 만들면 **`Artifact` 로 발행**하고 링크를 사용자에게 준다.

## 절대 규칙
- **제품 무관** — 어떤 SaaS 든 이 스킬로 설명한다. 특정 벤더 값을 정답처럼 박지 마라.
- **날조 금지** — 세션 자료에 없는 발견·수치·인용을 만들지 마라. 모르면 ⑤에 "확인 안 함"으로.
- 이건 **쉬운 설명본**이지 정식 보고서가 아니다. 정식본은 `/aar_review` 의 S3 문서다.
